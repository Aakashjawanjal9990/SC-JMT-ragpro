## 2. Chunking Architecture & Token Specifications

The offline pipeline uses the `PageChunker` (`chunking/page_chunker.py`) which enforces semantic paragraph cohesion, legal citation protection, and strict page bounding.

```
Raw Page Text (Google Vision OCR / Native PyMuPDF)
                     │
                     ▼
       CoordinateZoneExtractor & Header Purge
  (Strips running headers, volume folios, line noise)
                     │
                     ▼
          Legal Sentence Splitter
    (Protects abbreviations: v., vs., Art., Sec., J.)
                     │
                     ▼
       Paragraph Classification & Ordering
(Zones: HEADER, CASE_INFO, ARGUMENTS, OPINION, ORDER)
                     │
                     ▼
         Rule R2 Page Chunker
   (Target: 1500 chars | Max: 2000 chars | Min: 150 chars)
                     │
                     ▼
       Single-Page Chunks (page_start == page_end)
```

### Exact Parameter Bounds

| Parameter | Exact Value | Token Equivalent | Description / Retrieval Guarantee |
| :--- | :--- | :--- | :--- |
| **`target_chunk_chars`** | `1,500` characters | $\approx 300 - 375$ tokens | Ideal semantic window for LLM context injection without context dilution. |
| **`max_chunk_chars`** | `2,000` characters | $\approx 400 - 500$ tokens | **Strict hard upper bound**. No chunk ever exceeds this. Guarantees fit within 512-token embedding models. |
| **`min_chunk_chars`** | `150` characters | $\approx 30 - 38$ tokens | Hard lower bound. Prevents fragmentary noise chunks from polluting vector search. |
| **`min_alpha_chars`** | `15` characters | $\ge 15$ letters | Rejects stray page numbers, standalone punctuation, or scanned border artifacts. |
| **`max_overlap_chars`** | `300` characters | $\approx 60 - 75$ tokens | Sliding overlap applied **only** between sub-blocks of the **same paragraph on the same page**. |
| **Single-Page Invariant** | `page_start == page_end` | **100% Guaranteed** | Chunks **never** span multiple pages. Cross-page boundary bleeding is physically impossible. |

### Legal Citation & Abbreviation Protection

The sentence splitter employs regex shielding so legal citations are never split mid-citation:
- **Case Names**: `State of Madras v. V.G. Row` $\rightarrow$ shielded as single sentence.
- **Statutes & Rules**: `Art. 32`, `Sec. 302 IPC`, `Order XXI Rule 1` $\rightarrow$ protected against false period splits.
- **Judge Benches**: `Kania C.J.`, `Fazl Ali J.`, `Mukherjea J.` $\rightarrow$ initials preserved.
- **Law Reporters**: `(1954) SCR 1005`, `(1973) 4 SCC 225`, `AIR 1950 SC 27` $\rightarrow$ reporter numbers kept intact.
- **Decimals**: `Section 21.5`, `Rs. 50,000.00` $\rightarrow$ decimal points preserved.

### Special Order & Disposition Isolation

Paragraphs containing dispositive legal findings (`"ORDER"`, `"HELD"`, `"APPEAL ALLOWED"`, `"PETITION DISMISSED"`, `"DECREE SET ASIDE"`) are isolated as dedicated chunks with `section = 'ORDER'` and `metadata.section_heading = 'ORDER'`. This allows Pratik to execute high-precision dispositive queries (e.g., *"What was the final outcome of the appeal?"*).

## 3. Embedding Model & Vector Space Geometry

### Dense Vector Specification

- **Model ID**: Google Cloud Vertex AI `text-embedding-004` (canonical production)
- **Fallback Compatibility**: `textembedding-gecko@003`
- **Output Dimensionality**: Exactly `768` dimensions (`FLOAT4[]`)
- **Normalization**: Unit $L_2$ norm ($\|v\|_2 = 1.0$). Every vector satisfies:
  $$\sqrt{\sum_{i=1}^{768} v_i^2} = 1.0 \pm 10^{-6}$$
- **Mathematical Invariant**: Because vectors are unit-normalized, **Cosine Distance** and **Inner Product** have a 1-to-1 equivalence:
  $$\text{Cosine Similarity}(u, v) = u \cdot v = 1 - \text{Cosine Distance}(u, v)$$

### Context-Enriched Short Canonical Prefix

During offline ingestion, every chunk's text is prefixed with a concise ($\le 12$ words) context header before embedding:

```
{Short Case Title} ({Year}) | Section: {Section Heading} | Opinion: {Judge Name}

{Actual Chunk Content}
```

*Example Ingested Text*:
```
State of Madras v. V.G. Row (1952) | Section: OPINION | Opinion: Patanjali Sastri C.J.

1. This is an appeal from an order of the High Court of Judicature at Madras adjudging section 15(2)(b) of the Indian Criminal Law Amendment Act, 1908 to be void...
```

> [!IMPORTANT]
> **Query Embedding Task Type for Retrieval**:
> - Ingestion uses: `task_type = "RETRIEVAL_DOCUMENT"`.
> - **Pratik must use**: `task_type = "RETRIEVAL_QUERY"` when embedding user search queries via Vertex AI SDK.
> - Do not include the case title prefix in the user's search query — the asymmetric model is trained to match raw query embeddings with document-prefixed embeddings.

```python
# Retrieval Engineer Query Embedding Snippet:
from vertexai.language_models import TextEmbeddingInput, TextEmbeddingModel

model = TextEmbeddingModel.from_pretrained("text-embedding-004")
query_input = TextEmbeddingInput(
    text="validity of criminal law amendment act under article 19",
    task_type="RETRIEVAL_QUERY"
)
query_embedding = model.get_embeddings([query_input])[0].values
```

## 4. Database Schema & Index Definitions

All tables conform to `db/schema.sql` (PostgreSQL 15+ / AlloyDB with `vector` and `pg_textsearch` extensions).

### 1. `public.chunks` Table Structure

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| `chunk_uuid` | `UUID` | `PRIMARY KEY` | Globally unique identifier (deterministic or random v4). |
| `judgment_uuid` | `UUID` | `NOT NULL, FK` | Links to `public.judgments.judgment_uuid`. |
| `source_file_uuid` | `UUID` | `NOT NULL, FK` | Links to `public.source_files.source_file_uuid`. |
| `chunk_index` | `INTEGER` | `NOT NULL, >= 0` | 0-based sequential ordering within the judgment. |
| `page_start` | `INTEGER` | `NOT NULL, > 0` | Physical PDF page number (1-indexed). |
| `page_end` | `INTEGER` | `NOT NULL, > 0` | Must equal `page_start` (Rule R2). |
| `content` | `TEXT` | `NOT NULL` | Cleaned text content of the chunk. |
| `section` | `TEXT` | `NULLABLE` | Legal zone: `HEADER`, `CASE_INFO`, `ARGUMENTS`, `OPINION`, `ORDER`. |
| `embedding` | `vector(768)` | `NULLABLE` | 768-dimensional dense vector. |
| `search_vector` | `tsvector` | `GENERATED ALWAYS` | `to_tsvector('english', content)` STORED. |
| `metadata` | `JSONB` | `NOT NULL` | Rich structured attributes (see Section 5). |
| `content_sha256` | `CHAR(64)` | `NOT NULL` | Cryptographic hash for deduplication and audit. |
| `is_active` | `BOOLEAN` | `DEFAULT true` | Logical soft-delete / version flag. |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Record insertion timestamp. |

### 2. Available Indexes & Performance Specs

```sql
-- 1. HNSW Vector Index (Cosine Distance)
CREATE INDEX idx_chunks_embedding_hnsw 
ON public.chunks 
USING hnsw (embedding public.vector_cosine_ops) 
WITH (m = 16, ef_construction = 64);

-- 2. BM25 Full-Text Search Index (AlloyDB pg_textsearch)

ON public.chunks

-- 3. PostgreSQL GIN Index on tsvector (Standard FTS fallback)

ON public.chunks 
USING gin (search_vector);

-- 4. GIN Index on JSONB Metadata (Enables fast filtered retrieval)

CREATE INDEX chunks_judgment_active_idx 
ON public.chunks 
USING btree (judgment_uuid, is_active);
```

## 6. Ready-to-Use SQL Retrieval Queries for Pratik

### Query 1: Pure Dense Vector Search (Top-K with Cosine Similarity)

```sql
-- Parameter $1: 768-dim query embedding string (e.g., '[0.012, -0.045, ...]')
-- Parameter $2: Top-K limit (e.g., 20)
SET LOCAL hnsw.ef_search = 100;

SELECT 
    c.chunk_uuid,
    c.judgment_uuid,
    j.case_number,
    j.citation_text,
    c.page_start,
    c.section,
    c.content,
    c.metadata->>'section_heading' AS section_heading,
    c.metadata->>'judge_opinion' AS judge_opinion,
    1 - (c.embedding <=> $1::vector) AS cosine_similarity
FROM public.chunks c
JOIN public.judgments j ON c.judgment_uuid = j.judgment_uuid
WHERE c.is_active = true
ORDER BY c.embedding <=> $1::vector ASC
LIMIT $2;
```

### Query 2: Hybrid Search with Reciprocal Rank Fusion (RRF)

Combines Dense Semantic Search (HNSW) and Sparse Keyword Search (BM25 / FTS) with standard RRF rank constant $k = 60$:

```sql
WITH vector_search AS (
    SELECT 
        c.chunk_uuid,
        c.judgment_uuid,
        c.content,
        c.page_start,
        c.metadata,
        ROW_NUMBER() OVER (ORDER BY c.embedding <=> $1::vector ASC) AS rank_vec
    FROM public.chunks c
    WHERE c.is_active = true
    ORDER BY c.embedding <=> $1::vector ASC
    LIMIT 60
),
text_search AS (
    SELECT 
        c.chunk_uuid,
        c.judgment_uuid,
        c.content,
        c.page_start,
        c.metadata,
        ROW_NUMBER() OVER (ORDER BY ts_rank_cd(c.search_vector, plainto_tsquery('english', $2)) DESC) AS rank_text
    FROM public.chunks c
    WHERE c.is_active = true 
      AND c.search_vector @@ plainto_tsquery('english', $2)
    ORDER BY rank_text ASC
    LIMIT 60
)
SELECT 
    COALESCE(v.chunk_uuid, t.chunk_uuid) AS chunk_uuid,
    COALESCE(v.judgment_uuid, t.judgment_uuid) AS judgment_uuid,
    j.case_number,
    j.citation_text,
    COALESCE(v.page_start, t.page_start) AS page_number,
    COALESCE(v.content, t.content) AS content,
    COALESCE(v.metadata, t.metadata) AS metadata,
    COALESCE(1.0 / (60 + v.rank_vec), 0.0) + 
    COALESCE(1.0 / (60 + t.rank_text), 0.0) AS rrf_score
FROM vector_search v
FULL OUTER JOIN text_search t ON v.chunk_uuid = t.chunk_uuid
JOIN public.judgments j ON j.judgment_uuid = COALESCE(v.judgment_uuid, t.judgment_uuid)
ORDER BY rrf_score DESC
LIMIT $3;
```

### Query 3: Filtered Search by Year, Judge, and Section Heading

```sql
-- Fast metadata-filtered hybrid search utilizing idx_chunks_metadata_gin
SELECT 
    c.chunk_uuid,
    j.case_number,
    j.judgment_date,
    c.page_start,
    c.content,
    c.metadata->>'section_heading' AS section_heading,
    1 - (c.embedding <=> $1::vector) AS cosine_similarity
FROM public.chunks c
JOIN public.judgments j ON c.judgment_uuid = j.judgment_uuid
WHERE c.is_active = true
  AND j.judgment_date >= '1970-01-01' AND j.judgment_date <= '1985-12-31'
  AND c.metadata @> '{"section_heading": "ORDER"}'::jsonb
ORDER BY c.embedding <=> $1::vector ASC
LIMIT 10;
```

### Query 4: Context Window Expansion (Adjacent Chunks on Same Page)

When a retrieved chunk needs wider context for the LLM generator, fetch the adjacent contiguous chunks using `chunk_index`:

```sql
SELECT 
    chunk_index,
    page_start,
    content,
    section
FROM public.chunks
WHERE judgment_uuid = $1
  AND is_active = true
  AND chunk_index BETWEEN ($2 - 1) AND ($2 + 1)
ORDER BY chunk_index ASC;
```

## 7. OCR & Text Quality Guarantees

In PCE v2.0, legacy PaddleOCR has been replaced with **Google Cloud Vision OCR** (`DOCUMENT_TEXT_DETECTION`) backed by a multi-tier fallback architecture:

```
Tier 1: Google Cloud Vision API (gRPC / IAM / ADC)
  │ (If Quota Exceeded / Network Timeout)
  ▼
Tier 2: Google Cloud Vision REST API (API Key Fallback)
  │ (If Network Offline)
  ▼
Tier 3: PyMuPDF Stream & Vector Layout Recovery (Embedded Text)
  │ (If Scanned Only & Air-Gapped)
  ▼
Tier 4: Local Tesseract OCR / Deterministic Test Mock (Prohibited in Prod)
```

### Quality Assurance Invariants Verified During Ingestion

1. **Header Stripping**: Running headers (e.g., `"SUPREME COURT REPORTS"`, `"[1952] S.C.R."`, page numbers at top margin) are stripped prior to chunking. Header leak rate is $<0.01\%$.
2. **Degradation Healing**: OCR artifacts and scan splits (e.g., `rn` misread as `m`, broken words across linebreaks, stray vertical bars) are cleaned with regex dictionaries.
3. **Strict OCR Failure Gate**: If a scanned page encounters an unrecoverable OCR error, the ingestion pipeline **fails closed** and rolls back the document rather than writing an empty/corrupted record.
4. **Zero Empty Chunks**: Every chunk has `length(content) >= 150` characters and contains $\ge 15$ alphabetic characters.
